# Пайплайн полировки одиночного документа

Вид пайплайна `document` доводит **один** markdown-документ — чартер,
requirements, behaviour-спеку — до сходимости циклом «автор ↔ ревьюер».
Контур у него один (`doc`), и его сходимость терминальна: возвращаться
некуда, второго контура, который перепроверил бы результат, нет.

Нормативный текст — `disputatio-SPEC-002-doc-pipeline.md` (§1, §2, §3.2, §5.3).
Здесь — сквозной пример, исполнимый дословно.

## 1. Конфиг

Вид пайплайна выводится из **формы** секции `[pipeline]`, отдельной
подкоманды у него нет. Форма `document` и форма пары «спека + план»
взаимоисключающи: `document_path` рядом со `spec_path` — отказ загрузки, и
текст отказа перечисляет обе схемы.

```toml
# disputatio.toml
[pipeline]
document_path = "docs/charter.md"
# Журнал целостности P9 обязан лежать ВНЕ рабочего дерева — иначе отказ
# старта. Дефолт — пользовательский state-каталог (XDG).
# anchor_path = "~/.local/state/disputatio/anchors"
protected_branches = ["master", "main"]

# Чеклист контура `doc` объявляет ОПЕРАТОР целиком: вендоренного набора у
# него нет и быть не может — «что такое сошедшийся чартер» знает автор
# документа, а не это репо (§5.3).
[pipeline.checklists.doc]
# Пункт со смыслом «нет blocker/major-находок». Обязателен: без него
# правило V8 стало бы тихим no-op'ом через конфигурацию.
findings_item = "B3"

# Порядок объявления — часть чеклиста: он входит в его identity, попадает в
# снапшот как есть и определяет порядок пунктов в промпте ревьюера.
[pipeline.checklists.doc.items]
B1 = "границы и не-цели названы явно"
B2 = "каждое утверждение проверяемо по коду или по документу"
B3 = "нет blocker/major-находок"

[agents.author]
adapter = "claude_code"
model = "opus"

[agents.reviewer]
adapter = "claude_code"
model = "opus"

[limits]
max_rounds = 6
max_total_tokens = 2000000
max_wall_seconds = 7200
schema_retries = 2
```

Ключ `max_architectural_returns` в этой форме **отвергается**, а не
игнорируется: возвратов у вида нет, и молча проигнорированная настройка
оператора хуже отказа.

## 2. Предусловия

`run` исполняется в целевом git-репозитории и проверяет их fail-closed:

- рабочее дерево чистое — нет правок tracked-файлов и нет untracked-путей
  вне `.disputatio/`. Первый же ход автора делает `git reset --hard` и
  `git clean`, поэтому посторонний untracked-файл блокирует старт, а не
  уничтожается молча;
- текущая ветка не входит в `protected_branches`. Ветку runner не создаёт —
  это внешний эффект:

```bash
git switch -c docs/charter
```

## 3. Запуск

```bash
disp pipeline run --slug charter --config disputatio.toml --task task.md
```

`--task` принимает файл либо строку. Слаг именует каталог пайплайна и
журнал целостности; повторный `run` с тем же слагом отвергается — живой
пайплайн продолжают через `resume`.

Что происходит: заводится сессия `doc-r1` в режиме `document`, автор пишет
документ, пять doc-гейтов §6 проверяют пути, ссылки, якоря, `file:line` и
границу правок, ревьюер выносит вердикт по объявленному чеклисту. Раунд 1
approve'ом не закрывается: анти-сикофантия §5 SPEC-001 требует хотя бы
одного содержательного цикла — у этого вида она единственная защита от
«написал и сразу одобрил».

Наблюдать состояние (строго read-only):

```bash
disp pipeline status --slug charter --config disputatio.toml
```

Первой строкой печатается вид:

```
kind: document
pipeline: charter
phase: DOC_LOOP
documents: docs/charter.md
```

## 3a. `resume` и изменённый конфиг

`resume` сравнивает immutable-проекцию живого `[pipeline]` (вид, путь
документа, состав/порядок/роль чеклиста, добавленные гейты) с
версионированным доказательством, зафиксированным при `run`
(`semantic_proof.json`) — до чтения worktree и до любой мутации. Расхождение
останавливает `resume` (`SemanticDrift`), а не доезжает до ревьюера молча.

Практически это значит: воспроизводимость промпта и критерия сходимости
между запусками удостоверена. Подайте на `resume` тот же конфиг, что и на
`run`; изменивший immutable-часть конфиг останавливает `resume` с
перечислением разошедшихся полей, а не проходит молча. Изменяемые
runtime-настройки (`soft_max_pipeline_tokens`, `soft_max_pipeline_wall_seconds`,
`protected_branches`, `anchor_path`) по-прежнему берутся из живого конфига —
их правка между запусками легитимна и drift не создаёт.

Работало так с первой реализации SPEC-002 до закрытия issue #65
(WS-disputatio-65, TASK-001–TASK-004).

## 4. Остановка на внешней правке

Если между запусками документ правили руками, `resume` не станет
сбрасывать дерево, происхождение которого не доказано: он остановится,
покажет диф и потребует явного решения.

```bash
# санкционировать сброс и переиграть раунд (ручные правки теряются)
disp pipeline resume --slug charter --config disputatio.toml --discard-round

# либо принять правку как внешнюю и уйти в новую ревизию doc-r2
disp pipeline resume --slug charter --config disputatio.toml --adopt-external
```

Adoption fail-closed: диф, тронувший любой путь кроме `document_path`,
отклоняется целиком. Принятая правка коммитится операторским чекпоинтом,
поэтому первый ход новой ревизии её не стирает.

## 5. Результат

Сходимость (или эскалация) заканчивается экспортом в
`.disputatio/pipelines/charter/result/`:

| Файл | Что внутри |
|---|---|
| `manifest.json` | честная сводка: `converged`, фазы, ревизии с исходами, хеши артефактов, бюджет, причина эскалации и открытые находки |
| `pr_title.txt` | `docs: docs/charter.md` (с префиксом `[partial] ` при эскалации) |
| `pr_body.md` | документ вида, история фаз, ревизии контура `doc`, при эскалации — открытые находки |
| `publish.txt` | команды `git push` + `gh pr create --draft`; если remote или репозиторий однозначно не определяются локально — параметризованный шаблон с предупреждением |

`manifest.json` пишется последним и служит commit marker'ом: набор считается
валидным только при совпадении файлов и их sha256 с ним.

Коды возврата: `0` — сходимость, ненулевой — эскалация или отказ.

## 6. Что делает человек дальше

Публикация — внешний эффект, и её исполняет человек:

```bash
sh .disputatio/pipelines/charter/result/publish.txt
```

Пайплайн draft-PR не открывает сам и не пушит: он выдаёт полностью готовый
к публикации результат, а решение публиковать остаётся за оператором.

Пересобрать `result/` по существующему манифесту, ничего не прогоняя:

```bash
disp pipeline export --slug charter --config disputatio.toml
```
