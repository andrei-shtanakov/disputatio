## Группа A. Защиты, которые не срабатывают (fail-open) — чинить первыми

### A1 [major] `doc-scope` пропускает бинарники вне allowed — `verifier/doc_gates.py:278`
Бинарное изменение в `git diff` не даёт текстовых `---`/`+++`; `diff --git`
парсер игнорирует; пустой список распознанных путей **безусловно = PASS**.
Запрещённое изменение проходит границу контура молча.
→ Непустой патч без распознанных путей не должен считаться успехом.

### A2 [major] Пустая evidence-ссылка = доказательство — `contracts/checklist.py:48`
`GateEvidence.ref` — обычный `str` без `min_length`. `evidence=[{"kind":"gate","ref":""}]`
проходит: список непустой, `min_length=1` доволен, `validate_doc_review` содержимое
не смотрит. **Голословный approve проходит анти-галлюцинационные правила.**
→ Отвергать пустые и пробельные `ref`; artifact-evidence — требовать реальный диапазон.

### A3 [major] Повреждённая запись анкера отключает P9 — `events/integrity_anchor.py:191`
Читатель гасит любую ошибку JSON и пропускает строку. Повреждение последней
**полной** записи `pre_turn` → `last_record()` вернёт прежнюю `turn_completed`
или `None` → resume решает, что незавершённого хода не было, и control plane не сверяет.
→ Игнорировать только доказуемо оборванный хвост; полная невалидная строка — fail-closed.

### A4 [major] Заголовок в fenced code даёт несуществующий anchor — `verifier/doc_refs.py:183`
`## Example` внутри fence принимается за заголовок → ссылка `[#](#example)`
проходит `doc-anchors` зелёной, хотя секции в отрендеренном документе нет.

### A5 [major] Подменённый манифест с фазой DONE маскирует P9 — `runtime/pipeline_resume.py:356`
`ControlPlaneTampered` → `runner.fail` → `_fail` бросает `ValueError` на фазе DONE →
обработчик ловит только `KeyError` → исходное исключение теряется, `FAILED
(invariant_violation)` не пишется. Подделка, выставляющая терминальную фазу,
**отключает fail-closed обработку**.
→ **ПОЧИНЕНО, коммит `836330b`.** `_fail` не трогали (перезапись завершённого
результата — нарушение §2); обработчик вынесен в `_close_tampered`, ловит факт
неудачи, а пойманное уходит наружу причиной того же `ControlPlaneTampered`.
Внесён в `_TOLERATED_HANDLERS` поимённо (пин [DESIGN-016]). Fail-closed после
отказа держится анкером, а не манифестом. Мутация: возврат `except KeyError:
pass` роняет тест на `ValueError: пайплайн уже DONE` вместо `ControlPlaneTampered`.

## Группа B. Ложные срабатывания, блокирующие корректный сценарий

### B1 [major] Ссылки в fenced code проверяются как настоящие — `verifier/doc_refs.py:153`
Пример ```` ```markdown [пример](missing.md) ```` → обязательные `doc-paths`/`doc-links`
краснеют. **Корректный документ не может сойтись.** Инструмент для полировки спек
спотыкается о документы, состоящие из примеров в fence, — включая наши SPEC-002 и план.

### B2 [major] `doc-scope` принимает строки содержимого за заголовки — `verifier/doc_gates.py:280`
Строка содержимого `-- a/other.py` в unified diff становится `--- a/other.py` и
читается как файловый заголовок → ложный `scope_escape` → FAIL всего отчёта.

B1 и B2 — один корень с A4: **парсер идёт по строкам без состояния секции/fence.**
Чинить единым движением, не точечно.

## Группа C. Целостность состояния

### C1 [major] Повторный экспорт оставляет старый commit marker — `runtime/pipeline_export.py:156`
`_clear_stale` считает `manifest.json` каноническим и не удаляет; три файла
заменяются по одному, манифест пишется последним. Обрыв → старый манифест рядом
с частично обновлёнными файлами, SHA-256 не соответствуют содержимому.
**Наличие commit marker перестаёт означать завершённый экспорт (нарушение P8).**
Горько: `cli.py:357` предлагает повторный экспорт как способ починить испорченный результат.

### C2 [major] Lost update при двух resume — `events/pipeline_store.py:148`
Read-check-write без блокировки и версии. Два процесса проходят guard, второй
`atomic_write` затирает добавление первого в append-only коллекции.
→ Сериализация или compare-and-swap.

### C3 [major] Возврат не удаляет untracked припаркованной попытки — `runtime/pipeline_runner.py:686`
`reset_hard` без `clean` → `spec-rN+1.entry_hashes` пишет SHA файла вместо `absent`;
манифест лжёт про вход ревизии.
→ **ПОЧИНЕНО, коммит `d0703cb`.** Мутация роняет тест на `assert <sha> == 'absent'`.
Фейк `_FakeGit` переделан (раньше падал на `clean`, закрепляя отсутствие уборки).

## Группа D. Предусловия и конфигурация

### D1 [major] Адаптеры валидируются после создания durable-состояния — `runtime/composition.py:462`
Опечатка в `[agents.author].adapter` проходит предусловия; создаются анкер, каталог,
снапшоты, манифест, сессия — и только потом ошибка. **Пайплайн не восстановить
штатными командами**: `run` отвергнут анкером, `resume` перечитывает ту же опечатку.
Рядом в `cli.py:299` — комментарий, прямо обещающий сборку портов до мутаций.
→ **ПОЧИНЕНО, коммит `27791f6`.** `_resolve_adapters` собирает адаптеры обеих
ролей тем же `_build_adapter` и выбрасывает результат — именно сборка, а не
сверка имён по словарю: половина отказов приходит из конструктора (`codex`
ревьюером требует read-only worktree, ADR-004). Вызов первым после
`_require_toplevel`, до хранилища и журнала, — отказ не оставляет на диске ничего.

### D2 [major] `..` выходит за корень — `contracts/pipeline.py:41`
`RelativePath` проверяет только `is_absolute()`. `spec_path="../outside/spec.md"`
проходит; runner склеивает с `workspace_root`, читает и хеширует файл вне репозитория.

### D3 [minor] Экранированная reference-форма — `verifier/doc_refs.py:110`
`\[plan][missing]` даёт ложный `unresolved_ref` и «1 warning» в отчёте doc-reviewer'у.
Гейт остаётся PASS — шум, не блокировка.
→ **ПОЧИНЕНО, коммит `677f1dd`.**

**Внимание при работе над B1/B2/A4:** этот фикс — точечный, по экранированию.
Общий дефект парсера (нет состояния fenced code) им НЕ закрыт и остаётся
открытым в B1, B2, A4.

## Что это значит для метода

Внутренний цикл проверял компоненты **внутри границ, которые сам же провёл**.
Внешний ревьюер границ не знал и смотрел на стыки. Три вывода:

1. Мутационное тестирование не заменяет ревью: оно измеряет прочность
   существующих тестов и структурно слепо к недостающим.
2. Тесты писались от того, что код умеет разбирать, а не от того, из чего
   состоят реальные входные данные (fence, бинарники, повреждённые записи).
3. Пропуск терминального ревью — не формальность. Без него ветка ушла бы
   как готовая, с пятью нерабочими защитами.
