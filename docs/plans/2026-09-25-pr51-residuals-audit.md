## Заметки по строкам

**R1 — OPEN.** `ControlPlane._immutable_paths` (`runtime/pipeline_integrity.py:197-205`) хеширует
файлы пайплайна из `_PIPELINE_IMMUTABLE`. Сверх них он хеширует только `session.json`/`config.toml` и
`rounds/**` той ревизии, чей `artifact_root` передан, то есть текущей
(`composition.py:497-505` передаёт `artifact_root=artifact_root`). Runner при этом читает
соседние ревизии:
- `recompute_budget` на каждой записи манифеста читает `session.json` всех сессий
  (`pipeline_runner.py:300-319`);
- `_round_review` читает `review.json` припаркованной `pair-rN`
  (`pipeline_runner.py:1563-1575`).

Автор `spec-rN+1` может переписать файлы `pair-rN`, и P9 этого не заметит. Изменений в этой
области после PR #51 не было.

**R2 — CLOSED.** В WS-disputatio-65 (issue #65 CLOSED, TASK-001…005, PR #90–#94) `run` пишет
`semantic_proof.json`, а `resume` строит живую immutable-проекцию и сравнивает её с
доказательством fail-closed. Сравнение идёт сразу после манифеста (`PipelineResume._verify_semantics`,
`pipeline_resume.py:532-588`), при расхождении — `SemanticDrift` или `UnprovableSemantics`.
Живыми остаются только поля, сознательно классифицированные как `mutable`
(`pipeline_semantic_proof.py:77-89`: soft-лимиты, `protected_branches`, `anchor_path`). Так записано
в требованиях WS-65, это не дыра. `TODO.md:431` закрыт.

**R3 — OPEN.** `composition.py:522-528`: `except Exception:` → `load_session_state` → вернуть
состояние, если оно терминальное, иначе `raise`. Дискриминатор по-прежнему фаза на диске, а не
тип исключения. Любая ошибка (баг, `KeyboardInterrupt` сюда не попадёт, но попадёт, например,
`AssertionError`), поднятая после того, как ядро записало `FAILED`, будет проглочена как
«исход». Изменений после PR #51 нет.

**R4 — OPEN.** В production-коде у `read_pipeline_events` вызывающих нет, есть только тесты
(`tests/runtime/test_pipeline_runner.py`, `tests/events/test_pipeline_store.py`). Оговорка: P8
(`SPEC-002:162-176`) и §9 требуют, чтобы «парный читатель» поставлялся вместе с sink'ом. P11
(`:360-365`, PR #106) обосновал его терпимость ролью журнала и прямо назвал отсутствие
потребителей «сегодняшним фактом». Значит, находка скорее кандидат в «not planned» со ссылкой
на P8/§9, но такого решения нигде не записано.
